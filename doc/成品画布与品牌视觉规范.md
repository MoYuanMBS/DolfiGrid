# 成品画布与品牌视觉规范

> 本文档规定本项目后续新增或重做 HTML 排版模板的成品画布、Logo、文字卡片与业务图片规则。与旧文档的动态最低比例、内容自然增长约定冲突时，以本文档为准。

## 1. 适用范围与优先级

- 本规范适用于每一张最终导出的成品图，即每个模板唯一的 `.canvas` 画布及其导出 PNG。
- `layout`（用户给定的版式说明或参考布局）优先于本规范的默认位置；它规定内容区域、顺序、对齐和层级。
- 未给出 `layout` 时，使用本规范的默认规则。
- Markdown / frontmatter 负责可编辑业务内容和可替换图片；HTML 负责固定结构、Logo 槽位和媒体槽位；CSS 负责视觉风格与主题。
- 本规范暂为设计与模板契约。现有生成器尚未实现的字段，必须在代码实现后才可作为构建输入使用。

### 1.1 规范版本与旧档兼容

项目生成器同时支持两套规范：

| 规范 | 适用对象 | 识别方式 | 行为 |
|---|---|---|---|
| `legacy-v1` | 已归档的旧 Markdown 与旧模板 | 未声明 `spec_version` 时自动使用 | 保留 `layout_width`、`min_aspect_ratio`、`canvas_min_height` 和旧图片绑定行为；构建时输出归档兼容提示。 |
| `fixed-canvas-v2` | 后续新增或重做的模板 | frontmatter 明确声明 `spec_version: "fixed-canvas-v2"` | 强制固定宽高、固定画布溢出校验、Logo 契约与媒体槽位绑定。 |

- 不得根据模板名称、是否存在某个尺寸字段或现有 HTML 外观猜测规范版本；新规范必须显式声明。
- `legacy-v1` 只为复现归档产物而保留，不得作为新模板的起点。
- `fixed-canvas-v2` 模板必须在 HTML 中声明唯一的 `data-brand-logo` Logo 节点，并使用 `data-md-field="media"` 作为所有业务图片槽位。

## 2. 固定画布

### 2.1 基本规则

- 成品不是响应式网页。一套模板只对应一个固定的逻辑画布尺寸。
- 禁止根据正文长短、浏览器宽度或设备尺寸改变画布宽高比。
- 禁止使用媒体查询、`vw`、`vh`、百分比画布尺寸或 CSS 缩放来改变成品布局。
- 内容必须在指定画布内完成排版；内容过多时，应缩减内容、换用合适模板或重新给出 layout，不得自动拉长画布。
- 默认画布为横版 `1600 × 1200px`（4:3）。
- 需要 16:9 时，使用横版 `1600 × 900px`。竖版仅在 layout 明确要求时使用对应固定尺寸。

### 2.2 导出规则

- `canvas_width` 与 `canvas_height` 是逻辑排版尺寸，必须同时以 `px` 指定并锁死。
- `export_scale` 仅决定导出倍率，不改变布局坐标、字号、间距或元素比例。
- 推荐使用整数导出倍率 `2`、`3` 或 `4`；先导出高清母版，再等比缩小派生图，禁止将低分辨率成图放大。

`fixed-canvas-v2` Markdown frontmatter 的写法：

```yaml
spec_version: "fixed-canvas-v2"
canvas_width: "1600px"
canvas_height: "1200px"
export_scale: 3
```

在 `fixed-canvas-v2` 中，`layout_width`、`min_aspect_ratio` 和 `canvas_min_height` 均为废弃字段，不能与固定画布字段混用。

## 3. Logo

### 3.1 必须出现

- 每张成品画布必须有且仅有一个 Logo。
- 未给定 layout 时，Logo 默认置于画布顶部，清晰可辨且不被正文、业务图片或装饰遮挡。
- 给定 layout 时，可改变 Logo 位置，但仍须保持可辨识、留有安全边距，并不得被裁切。
- Logo 的最小显示宽度为画布宽度的 `10%`；默认安全边距不小于画布短边的 `3%`。layout 有明确尺寸时，以 layout 为准。

### 3.2 版本使用

- 项目提供三种固定 Logo 版本，由模板资产层指定；业务文案不需要写入 Markdown。
- 一张成品只能选用其中一个版本，不得混用、并列或在同一画布重复展示多个版本。
- 允许在 HTML 模板中固定当前版本。若以后需要从 frontmatter 选择，必须限制为预定义的三个合法值并完成构建校验。

### 3.3 无边框要求

- Logo 本体及其容器不得有 `border`、`outline`、描边式包围线、相框、徽章外框或任何围合式卡片边框。
- 可以使用不围合 Logo 的独立装饰，例如光点、线条、纹理、图形或留白；装饰不得形成框住 Logo 的视觉效果。
- 不得使用会削弱识别度的裁切、遮罩或与背景过度接近的颜色。

## 4. 文字与版式

- 有 layout 时，内容顺序、区域划分、对齐关系和信息层级必须遵循 layout；主题、配色、装饰和组件细节可在不破坏 layout 的前提下变化。
- 无 layout 时，优先建立清楚的标题、正文/价格、提示与行动信息层级；Logo 位于顶端。
- 文字可以使用带边框的卡片、表格、提示块和信息容器。此许可只适用于文字/数据内容，不适用于 Logo 或业务图片。
- 业务文字、价格、标签、要求、须知等可变内容必须保留在 Markdown 或 frontmatter 中，不得写死在 HTML/CSS。

## 5. 业务图片

### 5.1 无边框要求

- 业务图片本体及其容器不得有边框、描边、相框、包围线或卡片外框。
- 图片可使用圆角、裁切、透明蒙版、阴影或非围合式装饰，但这些效果不得呈现为边框或相框。
- 纯装饰背景不属于业务图片，可由主题/背景资产管理；它不得承担可编辑业务内容。

### 5.2 可替换接口

- 每张业务图片必须占用明确的媒体槽位，例如 `data-md-field="media"`。
- 图片路径必须来自 Markdown frontmatter 的 `images` 列表，按既有媒体槽位顺序绑定；HTML 和 CSS 不得写死业务图片文件名或 URL。
- 图片文件继续放在 `assets/insert-png/`。替换图片时只替换该目录中的文件并更新 Markdown 的 `images` 字段。
- 图片必须保持原始宽高比，不变形；是否裁切由模板媒体槽位明确规定，不能由替换图片临时改变布局。
- 图片数量多于可用媒体槽位、路径不存在、或图片无法绑定时，生成器必须报错。

示例：

```yaml
images:
  - "package-01.png"
  - "package-02.png"
```

## 6. 模板验收清单

- [ ] `.canvas` 的宽度和高度均为明确的 px 值，且符合指定比例。
- [ ] 无响应式断点、动态比例或随内容增长的成品画布。
- [ ] 每张成品恰有一个清晰可见的 Logo，且使用单一版本。
- [ ] Logo 没有任何形式的边框或围合式容器。
- [ ] 业务图片可通过 Markdown `images` 替换，且没有边框或相框。
- [ ] 文字卡片如有边框，只包住文字/数据内容，不包住 Logo 或业务图片。
- [ ] 给定 layout 时，内容顺序、区域和对齐均符合 layout。
- [ ] 导出高清母版后，再以整数倍率缩小派生图。

## 7. SVG 调用与主题着色

- SVG 原始资产只存放在 `assets/svg/`；所有 `url(...svg)`、`mask-image` 与 SVG 图层组合只能写在 `css/svg/*.css`。
- `assets/svg/` 中的每个 SVG 都必须在 `css/svg/` 的资产注册样式中拥有一个语义类，即使该资产暂未被任何模板使用；不得因“当前未调用”而漏登。
- `css/themes/*.css` 只为 SVG 提供 `--svg-*` 颜色变量，不得直接写 SVG 资产路径。
- 单色黑色 SVG 使用 CSS mask，并由主题变量着色。
- 彩色 SVG 必须拆出同尺寸的 `*-ink.svg`（仅黑色部分）和 `*-color.svg`（仅非黑色部分）。CSS 以 `::before` 输出主题色墨线层、以 `::after` 输出彩色层，彩色层始终位于墨线层上方；不得直接把 `*-ink.svg` 覆盖在完整原图上，否则会遮住叠放的彩色细节。
- 黑色必须按最终 SVG 绘制结果判断：显式 `#000` / `black`、从父元素继承的黑色，以及没有 `fill` 时 SVG 默认的 `fill: black` 都属于可着色黑色部分；不得只按源码中是否出现 `#000` 判断。
- `filter`、`feColorMatrix` 和对整张 SVG 的 CSS 过滤不得用于黑色局部着色，因为它们会改变其他颜色。
- 深色但非黑色的设计色（例如 `#231815`）默认保留原色；只有在资产登记中明确标为黑色墨线时才可转为 mask 着色。
