# 项目与代码规范

## 1. 项目定位

本项目用于将结构化 Markdown 生成固定尺寸的 HTML 排版稿，并进一步导出为图片。

- 不是前后端项目。
- 不做响应式布局。
- HTML 是固定画布排版模板。
- CSS 负责主题与视觉，不承载业务文字。
- Markdown 是内容来源。
- Node.js 脚本负责校验、绑定和输出。

Markdown 输入语法请参阅 [Markdown排版生成规范.md](Markdown排版生成规范.md)。

## 2. 目录职责

```text
assets/insert-png/       Markdown 可插入图片的唯一目录
css/themes/              颜色主题，例如 bright.css
css/base.css              全局基础样式
css/layout.css            固定画布与布局样式
css/components.css        卡片、列表、须知等组件样式
css/utilities.css         工具类
doc/                      项目、代码和 Markdown 规范
new-project/build.js      用户构建入口
new-project/generate.js   通用 Markdown → HTML 生成引擎
new-project/export-images.js  HTML → PNG/SVG 导出器
original-md-files/        用户实际编辑的 Markdown 原稿
output/                   生成后的 HTML、PNG 和 SVG 文件
标准格式/                 HTML 排版模板
fonts/                    本地字体文件
```

## 3. 构建流程

用户只调用构建入口：

```powershell
node .\new-project\build.js 体验护航.md
```

需要生成最终图片时使用：

```powershell
node .\new-project\build.js 体验护航.md --export=true
```

`--export` 默认是 `false`。开启后会先生成 HTML，再输出同名的 PNG 和 SVG；SVG 是浏览器将 HTML 画布序列化后的导出文件，适合作为固定版式成品，不视为可逐图层编辑的矢量源稿。

流程：

```text
original-md-files/体验护航.md
→ build.js 读取 frontmatter
→ 选择 HTML 模板与 CSS 主题
→ 校验 assets/insert-png/ 中的图片
→ generate.js 解析正文并绑定模板
→ output/体验护航.html
→ （仅 --export=true）export-images.js → output/体验护航.png + output/体验护航.svg
```

`build.js` 只允许传入文件名，不允许 Markdown 指向项目外路径。

## 4. 脚本职责边界

### build.js

- 接收 `original-md-files/` 中的 `.md` 文件名。
- 读取 frontmatter 的 `template`、`theme`、`images` 等构建配置。
- 校验模板、主题和图片是否存在。
- 计算生成 HTML 所需的相对资源路径。
- 调用 `generate.js`。
- 当 `--export=true` 时调用 `export-images.js`。

### generate.js

- 解析 frontmatter 和 Markdown 正文。
- 处理标题、列表续行、`/|`、`{{skip}}` 和透明占位符。
- 默认按模板 DOM 顺序绑定，`[role:id]` 仅作显式覆盖。
- 读取模板副本后生成新 HTML，绝不修改原始模板文件。
- 处理正文主标题、装饰文字、卡片内容和图片媒体槽位。
- 校验最终解释权和可见占位符等固定规则。

### export-images.js

- 使用 Playwright 打开生成后的 HTML，并通过 `html-to-image` 导出 PNG 与 SVG。
- 导出期间启动仅供本机使用的临时静态服务，确保本地 CSS、字体和图片能被浏览器正常读取。
- 不修改 Markdown、模板或 CSS；仅在 `output/` 写入导出产物。

## 5. Frontmatter 构建配置

每个 Markdown 文件顶部至少指定模板和主题：

```md
---
template: "susu_tactical_ui_template"
theme: "bright"
subtitle: "TACTICAL SERVICE MENU & PRICE LIST"
hud_tag: "TACTICAL SERVICE MENU // 战术导引菜单"
decor_block_height: "100px"
images:
  - "image-01.png"
  - "image-02.png"
---
```

规则：

- `template` 对应 `标准格式/<template>.html`。
- `theme` 对应 `css/themes/<theme>.css`。
- 图片只写文件名，实际位置固定为 `assets/insert-png/`。
- `images` 按顺序绑定未跳过的媒体槽位。
- `title` 不允许写在 frontmatter；标题必须写在 Markdown 正文。
- `subtitle`、`hud_tag` 和 `label.*` 是可变文字。
- `decor_block_height` 控制底部透明装饰区高度；`canvas_min_height` 可选地控制画布最小高度。
- 须知以普通 Markdown 列表写在 `## [section:notice]` 下，不写在 frontmatter。

## 6. HTML 模板契约

新模板必须保留以下约定，生成器才能工作：

```html
<link rel="stylesheet" href="../css/themes/bright.css" data-theme-stylesheet>

<section data-md-role="section" data-md-id="example">
    <h2 data-md-scope="example" data-md-field="title"></h2>
</section>

<div data-md-role="card" data-md-id="example-card">
    <h3 data-md-scope="example-card" data-md-field="title"></h3>
    <ul data-md-scope="example-card" data-md-field="items"></ul>
    <div data-md-scope="example-card" data-md-field="media"></div>
</div>
```

属性职责：

- `data-theme-stylesheet`：允许 `build.js` 替换主题 CSS。
- `data-md-role`：可绑定元素类型，例如 `section`、`card`、`document`。
- `data-md-id`：可选的显式绑定 ID。
- `data-md-scope`：字段所属的 section/card ID。
- `data-md-field`：字段名称，例如 `title`、`items`、`media`、`label`。
- `data-bind`：直接对应 frontmatter 键名，用于 `subtitle`、`hud_tag`、`label.*` 等文字。

固定最终解释权区域必须保留，不得设置为 Markdown 可覆盖字段。

## 7. CSS 规范

- 所有颜色、渐变、阴影和主题变量只写在 `css/themes/`。
- `base.css`、`layout.css`、`components.css`、`utilities.css` 不写主题颜色字面量。
- 新主题只新增 `css/themes/<theme>.css`，变量名称必须与现有主题一致。
- 图片样式必须保持 `width: 100%`、`height: auto`，不裁切、不变形。
- 空占位符必须透明，只通过最小高度保留空间。

## 8. 代码维护规范

- 不在 `generate.js` 写 D1、D2、D3 或具体业务名称。
- 不在 JS 中写死某个模板的卡片 ID 映射。
- 新增可变文字时，优先给 HTML 添加 `data-bind`，并在 Markdown frontmatter 添加同名键。
- 新增内容位置时，优先使用 DOM 顺序绑定；只有确实需要固定定位时才添加 `[role:id]`。
- 新增图片槽位时，添加 `data-md-field="media"`，图片由 `images` 顺序注入。
- 修改解析规则时，同步更新 `Markdown排版生成规范.md`。
- 修改构建约定、目录或模板契约时，同步更新本文档。

## 9. 验收清单

每次修改生成相关代码后，至少确认：

- Markdown 文件名、模板名和主题名均存在。
- 生成 HTML 的 CSS 相对路径正确。
- 标题、HUD、装饰标签和列表内容都可见。
- `/|` 左右栏对齐正常。
- 续行和透明占位符高度正常。
- 图片顺序、比例和路径正确。
- `{{skip}}` 不留空白。
- 最终解释权仍存在。
- 最终 HTML 没有可见占位文本。
- 若开启导出，PNG 与 SVG 均已生成且 PNG 的视觉内容正确。
